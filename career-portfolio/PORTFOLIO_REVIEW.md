# 포트폴리오 완성도 검토

대상: `career-portfolio/KimSunWoo_WebDeveloper_Portfolio_2026.pdf`  
검토일: 2026-10-13

## 충족

- 웹 포트폴리오 서비스가 분량의 중심이다. 화면, 인증, 캐시, 장바구니, 결제, 배포를 코드 경로와 함께 적었다.
- 자동매매는 전략·수익률이 아니라 주문 상태와 멱등성으로 적었다. 첫 설명에 바이브코딩과 PAPER 진행 중을 표시했다.
- REAL 매매, 수익, 측정되지 않은 캐시 개선율, 미커밋 DB 멱등성을 완료 성과로 쓰지 않았다.
- AI 에이전트 저장소는 열리지 않았다고 적고, 자동매매와 운영 연동된 것처럼 쓰지 않았다.
- Python 프로젝트는 한 페이지이고 모델 성능은 빼 두었다.
- 안전모 작업은 프로토타입으로 분류했다.
- 운영 사이트의 실제 화면을 캡션과 함께 넣었다.

## 부족

- 관리자 화면이 없다. 비밀번호 입력을 자동화하지 않았다.
- 자동매매 UI 스크린샷이 없다. 앱을 실행하거나 주문을 내지 않았다.
- AI 에이전트는 소비 측 공개 문서만 있어 1페이지가 근거 공백에 가깝다. 인증 후 구현이 확인되기 전에는 늘리지 않는 편이 맞다.
- 백엔드·프론트 테스트를 이번 세션에서 다시 실행하지 않았다. PDF는 테스트 파일과 기존 검증 문서의 존재를 말할 뿐, 현재 HEAD의 통과를 주장하지 않는다.
- 웹 포트폴리오에서 AI 도구를 얼마나 썼는지는 여전히 미확정이다. 문서는 그 미확정을 유지한다.
- 커뮤니티 캡처에 성능 개선 제목이 보인다. 본문은 그 수치를 성과로 쓰지 않는다고 적어 두었으나, 이미지만 보는 사람은 제목을 결과로 읽을 수 있다.

## 개선 순서

1. GitHub 인증 후 `Auto_Trading_AI_Agent`를 읽고, 공개 승인된 범위만 12페이지를 구현 근거로 교체한다.
2. 관리자 화면과 자동매매 읽기 전용 화면을 받아 4·9페이지 근처에 넣는다.
3. `./gradlew test`와 자동매매 `npm test`를 안전한 로컬에서 실행해 통과 여부를 증거 표에 갱신한다.
4. 장바구니 DB 멱등이 main에 반영되면 “미커밋” 서술을 커밋 해시로 바꾼다.
